# 雑誌 UI リデザイン設計書

**日付:** 2026-11-08
**対象:** 公開サイト全体（トップ・作品詳細・アルバム一覧・タグページ）と管理画面の見た目
**参照試作:** `docs/superpowers/specs/assets/2026-11-08-magazine-prototype.html`（three.js の使い捨て試作。カメラ・紙のしなり・めくりの動きの基準。画像は `/files/p0.png`〜`p5.png` を参照しているので、試す場合はサンプル画像を同じ場所に置く）

---

## 意図

サイトの UI に一貫性を持たせたい。各画面のスタイルがバラバラ（全体 CSS・レイアウト・各ページの `<style>`・インライン指定に分散、カード部品が 6 種類）で、見た目がそろっていないのが出発点。

ニューモーフィズムを試したが「微妙」だった。代わりに方向性として選ばれたのは、参考動画（3D モデルを中央で動かし、計器のような半透明パネルが周りを囲む HUD 構成）を、サイト名「ジャンクジャーナルジャーニー」に合わせて **空中に浮いた雑誌のページがめくれる** 表現に置き換えたもの。

目的は 2 つで、性格が違う。

1. **トップページは「見せる」**: 訪問者が開いた瞬間に作品が目に入り、自然に作品を見て回る（回遊する）きっかけを作る。ビジュアル重視。
2. **作品詳細は「読む」**: 絵を見ることが本旨。ノイズを極力減らし、絵を本来の色と形で見せる。ただしページをめくる手触りは残す。

## ゴール

- 開いた瞬間に、ランダムに選ばれた作品が雑誌のページとしてめくれていくトップページ
- 作品一覧が画面の端で常に流れ、気になった作品をその場で開ける
- 作品ごとに URL があり、共有・直接アクセス・ブラウザの戻るが自然に効く
- 作品詳細では、絵が歪まず、色も変わらず、パネル類が絵に重ならない
- 公開サイトと管理画面の見た目が、同じ色・文字・部品の規則でそろう

## ゴールではないこと

- 管理画面に 3D 表現を入れること（見た目の規則をそろえるだけ）
- データモデルの変更（作品説明はすでに `images.description` にある。入力欄を足すだけ）
- 既存 URL（`/albums/<slug>`, `/tags/<slug>`）の変更

## やってはいけないこと（技術的に動いても失敗とみなす）

- 作品詳細で、パネル・ラベル・ボタンが絵に重なる
- 作品詳細で、絵が斜めに歪んだまま、照明で色が変わったまま、ぼけたまま表示される
- 作品詳細で、ふわふわ漂う動きが絵を見る邪魔になる
- ズーム中にパネル類が絵の邪魔をする
- めくっているページが、下のページに埋まって見える（試作で一度起き、修正済み）
- 3D が重くてトップがなかなか表示されない、スマホで操作が引っかかる

## 見た目の規則（全画面共通）

参考動画の HUD の雰囲気に寄せる。

- 背景: 生成りに近いオフホワイト（試作では `#f1eee8`）
- アクセント: オレンジ `#ff5714`（既存の `--accent` と同じ）
- 文字: 本文は今の日本語フォント（Noto Sans JP）。計器風のラベル・数値・状態表示は小さな等幅文字（英大文字、字間広め）。大きな状態ラベル（`TURNING` / `HOLDING` など）はオレンジの太字
- パネル: 白の半透明（約 70%）＋細い線（`rgba(0,0,0,.08)` 程度）＋小さな角丸。影はほぼ付けない
- 部品は 1 系統にまとめる: パネル、ボタン（主・副・危険）、入力欄、チップ（タグ）、カード、ラベル。全画面がこの部品だけで組めるようにし、ページごとの個別スタイルとインライン指定をなくす

**判断（Claude）:** 今の緑（`--text: #07a25c` などの緑系）は主役の色から外し、文字はインク色（濃いグレー）にする。参考の雰囲気（白＋オレンジ＋細い線）を優先したため。緑を残したい場合は、ラベルや状態表示の一部にだけ使う。

## トップページ

### 画面構成（PC）

- **左の作品一覧（レール）**: 画面左に細い縦の列。小さな正方形のサムネイルが上へ向かってループで流れ続ける
  - ホバーすると、流れが慣性でゆっくり止まり、そのサムネイルが少し拡大する
  - タイトル・投稿日・タグ（所属アルバムがあればその名前も）のポップアップが出て、作品の上を緩やかに漂う
  - マウスが離れると、また流れ始める
- **中央の雑誌**: 残りの領域全体。後述の「見せる」ページめくり
- **計器風パネル**: 「NOW OPEN（開いている作品名・ページ数・日付）」「状態ラベル（TURNING / HOLDING / RIFFLE）」「AUTO TURN ・ 02 / 06」などを画面の隅に置く。**トップでは絵に重なってもよい**
- **雑誌の下の幾何学アニメーション**: 雑誌の下にオレンジの細い円・破線の円・目盛りが傾いて重なり、ゆっくり回る（試作のもの）

### 画面構成（スマホ）

- 作品一覧は画面上部の横長の帯。左へループで流れる
- タップでサムネイルが拡大し、メタ情報がポップアップする（ホバーの代わり）
- その下に雑誌。構図は PC と同じ考え方（ピントの合ったページの重心を表示領域の中央に）

### 作品一覧（レール）の範囲（判断: Claude）

- 公開されている全画像を新しい順に流す。今の「24 件ずつのページ送り」はなくす
- 最初は直近の数十件を HTML に含め、流れていくのに合わせて続きを API から読み足す
- サムネイルは公開用（長辺 2000px）では重いので、アップロード時に小さい版（長辺 400px 程度の WebP）も作って R2 に置く。既存の画像は一度だけ小さい版を作る処理を流す
- 件数が少なく画面を埋められないとき（タグページなど）は、ループさせずに並べるだけにする

### ランダムな選び方（判断: Claude）

- 選ぶのはブラウザ側。サーバーは候補（2 ページ以上のアルバムの一覧と、1 枚ものの画像の一覧）を渡す。サーバー側で選ぶと、HTML のキャッシュや検索結果がランダムな内容に引っ張られるため
- JavaScript が動く前の HTML には、ランダムではない固定の内容（最新のアルバム、なければ最新の数枚）を入れておく
- 候補が 1 件しかない場合は、それを開く。1 枚ものが 1 枚しかない場合は 1 枚の紙として浮かべる

### 「見せる」ページめくり

- **何を開くか**: 訪問するたびにランダムに選ぶ。2 ページ以上のアルバム 1 冊、または何枚かの 1 枚もの作品を束ねた「仮の雑誌」
- **雑誌の形**: ラフに開いた雑誌が空中に浮かび、ゆっくり上下に漂い、わずかに揺れる。真下にぼんやりした影
- **紙のしなり**: 背表紙のところで紙が立ち上がり、外側へ行くほど重力で垂れる。めくっている途中は背に近い側が先に動き、外側が遅れてついてくる（紙がたわみながら返る）。上下の角はわずかに余計に垂れる
- **めくりの順序**: 約 2.5 秒ごとに 1 枚めくれる。最後まで行ったらパラパラと一気に戻り、繰り返す
- **重なり**: ページ同士は紙の面に垂直な方向に間隔を取る。めくっているページは束から浮いて通る（下のページに埋まらない）
- **表紙**: 内側は紙の色、外側の縁だけオレンジ
- **紙面**: 生成りの紙に作品を余白付きで配置。下に小さく `JUNK JOURNAL JOURNEY`
- **カメラ（ユーザーが決めた構図）**: 注視点から見たカメラの相対位置 `(1.34, 2.89, 0.94)`、焦点距離 44mm、ぼけ（BokehPass の aperture）0.006。高めの位置から見下ろす寄りの構図
  - **ピントの合っている右ページの重心が、常に画面の中央に来る**ように、向きと距離を保ったままカメラを平行移動して追従する（雑誌が漂っても柔らかく追う）
  - 手持ちカメラのような、ごくわずかな揺れ
  - ピントは右ページの重心。手前と奥は大きくぼける
- 参考実装: 試作の `shapePage()`（しなりと重なり）と、カメラの追従部分

## 作品詳細

### 開き方と URL

- トップの作品一覧のサムネイル、またはトップの雑誌をタップ・クリックすると、**ページを読み込み直さずに同じ画面のまま**作品詳細に切り替わる
- 同時に、アドレスバーの URL をその作品のものに書き換える（History API）。ブラウザの戻るで直前の状態に戻る
- その URL を直接開いた場合も、サーバー側で同じ画面を「その作品を開いた状態」で返す（共有リンク・再読み込み・検索エンジンに対応）
- **URL（判断: Claude）**
  - アルバム: 今の `/albums/<slug>` をそのまま使う。特定のページから開くときは `/albums/<slug>?page=<n>`（1 始まり）
  - アルバムに入っていない 1 枚もの: `/works/<画像ID>`（新設）
  - 2 ページ以上のアルバムに入っている画像のサムネイルは、そのアルバムをその画像のページから開く（現在のフィードと同じ規則。複数のアルバムに入っていれば最新のアルバム）
  - 古い形式のアルバム slug からの 301 リダイレクト（実装済み）は維持する
  - **1 ページだけのアルバム（判断: Claude）**: 雑誌として成り立たないので、その画像のサムネイルは 1 枚ものと同じく `/works/<画像ID>` を開く。`/albums/<slug>` を直接開いた場合は 1 枚の紙として表示する
  - **`/works/<画像ID>` はすべての画像で有効（判断: Claude）**: アルバムに入っている画像でも、その 1 枚を紙として表示し、所属アルバムへのリンクを添える。サムネイルからの遷移先は上の規則（2 ページ以上のアルバムならアルバム）に従う
- **閉じたときの戻り先（判断: Claude）**: 開いた元の一覧に戻る。トップから開いたら `/`、タグページから開いたら `/tags/<slug>`。作品の URL を直接開いた人が閉じた場合は `/`（トップ）。いずれも履歴があれば「戻る」と同じ動きにし、なければ `history.replaceState` で一覧の URL に置き換える

### ページと画像の対応（判断: Claude）

- 画像 1 枚 = 紙の片面 1 ページ。見開きは 2 ページ
- 最初の見開きの左は表紙の内側（無地の紙）、右が 1 ページ目。以降、左右に 1 枚ずつ並ぶ
- 枚数が奇数のときは、最後の見開きの右に裏表紙の内側（無地）が来る
- ページ数の表記（`02 / 06`）と `?page=<n>` は、この画像の順番（アルバムの並び順、1 始まり）を数える
- 「ピントの合うページ」はトップでは右ページ、詳細では開いているページ（指定ページを含む見開きの、そのページ）

### 見え方（「読む」）

- カメラが斜めの寄りの位置から、**紙面の正面へ回り込む**
- 絵は**本来の色と形**で見せる
  - 表示中のページは平らに戻し、歪みをなくす
  - 絵には照明による色の変化とピントのぼけを掛けない（判断: Claude。紙面の絵の部分は照明の影響を受けない描き方にする）
  - 雑誌らしさは、めくるときの紙のしなりと、紙面の余白・縁で残す
- ふわふわ漂う動きは最小限（判断: Claude。詳細中は漂いと手持ちの揺れを止める）
- **パネル類の存在感は最小限で、絵には重ねない**。絵の外側の余白にだけ置く
- **ズーム**: 拡大したときはパネル類を隠すか端に細くたたみ、絵に画面を明け渡す。ズームをやめると戻る
- アルバムに入っていない 1 枚ものは、1 枚の紙として同じ枠の中に表示する（判断: Claude）

### 表示する情報

- タイトル、作品説明（ディスクリプション）、タグ、投稿日
- タグはタグページへのリンク
- アルバムの場合はアルバムのタイトル・説明と、今のページ数 / 全ページ数

### 操作（判断: Claude）

- ページ送り: 左右の矢印キー、紙面の左右の端のクリック・タップ、スマホではスワイプ。めくるときは紙がしなる
- ズーム: ダブルクリック・ダブルタップ、ピンチ、Ctrl＋ホイール。ズーム中はドラッグで移動
- 閉じる: Esc、✕、ブラウザの戻る。トップの状態（めくり再開）に戻る

## 他の画面

トップの雰囲気（色・文字・パネル・部品）に寄せる。3D は使わない。

- **アルバム一覧（`/albums`）**: アルバムの表紙を並べる。各アルバムを押すと作品詳細（そのアルバム）を開く
- **タグページ（`/tags/<slug>`）**: 判断（Claude）: トップと同じ構成で、作品一覧と「見せる」雑誌をそのタグの作品に絞る。そろえたほうが一貫性が出て、作り分けも減るため
- **管理画面**: 同じ部品（パネル・ボタン・入力欄・チップ）で組み直す。サイドバー、ダッシュボード、アップロード、画像管理、アルバム管理、ログイン
- **既存の表示部品の置き換え**: フィードのライトボックス（`Lightbox.astro`）と、アルバムの comimi ビューワー（`AlbumViewer.astro`、`albums/[slug].astro`）は、作品詳細に置き換える。不要になったら削除する

## Bluesky 投稿のリンク

- 自動投稿の本文に入れるリンクを、サイトのトップから **その作品のページ `/works/<画像ID>`** に変える（ユーザー確認済み）
- アップロード画面の文面の自動作成（プレビュー）も同じ URL にする。アップロード前は ID が決まっていないので、プレビューでは「作品ページの URL」と分かる仮の表記にし、サーバー側で実際の URL に置き換える（判断: Claude）

## 作品説明の入力

- アップロード画面（画像ごと）と画像管理の編集欄に、作品説明の入力欄を足す
- アクション側（`uploadImage` / `updateImage`）は `description` をすでに受け取れる

## 制約・品質

- **技術**: three.js（試作で使用）。three.js はトップ・作品詳細・タグページでだけ読み込み、管理画面やアルバム一覧では読み込まない
- **重さ**: 雑誌に貼る画像は公開用の圧縮済み画像（長辺 2000px の WebP）を使う。最初の表示を待たせないよう、3D の準備ができるまでは静的な表示（例: 最初の見開きの画像）を出しておく
- **タブが見えていないときは描画を止める**。デバイスピクセル比は上限を設ける
- **動きを減らす設定**（`prefers-reduced-motion`）の人には、自動めくり・漂い・回転を止め、手動のページ送りだけにする
- **WebGL が使えない環境**では、平面の表示（作品の画像と情報）に切り替える
- **検索・共有**: 作品の URL を直接開いたとき、タイトル・説明・タグ・画像の `alt` が HTML に含まれていること（JavaScript 実行前でも内容が分かる）
  - タイトルがない作品（判断: Claude）: 表示上のタイトルは「無題」。`alt` は「無題（2026年11月8日）」のように投稿日を添える。説明があれば、説明の先頭を `alt` に使う
- **管理画面への導線**: ログイン中だけ出る「管理画面」リンクは新しいヘッダーにも残す（秘密の URL を含むページはキャッシュさせない仕組みは維持）
- **公開・非公開**: 元画像（`originals/`）は今まで通り公開しない

## ビルダーに任せること

- 3D の実装方法の細部（ジオメトリの分割数、紙の質感、ライティング、影の作り方）。試作の見た目を下回らないこと
- 作品一覧の流れる速さ・慣性の効き方・ポップアップの漂い方の数値
- ランダムに選ぶときの重み付け、1 枚もの作品を何枚束ねて「仮の雑誌」にするか
- スマホでの雑誌の構図の細かい調整
- 部品（パネル・ボタンなど）の具体的な寸法・余白
- 既存の CSS（`global.css`・`neumorphism.css` のお試し版など）をどう整理するか。お試し版のニューモーフィズム（ブランチ `spike/neumorphism`）は採用しない
